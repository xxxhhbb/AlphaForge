# AlphaForge 路线图

## 路线图目标

下一阶段不再以“再增加模块”为主要目标，而是把一条已跑通的真实路径收敛成研究质量更好、报告更清楚、六组更可靠、前端更可信的产品。

## P0：GitHub 与文档可接手

目标：外部人或 AI 克隆后，30 分钟内理解产品并跑起一个安全入口。

交付：

- AlphaForge 根 README；
- 本地、Docker、配置、API、架构、安全、前端和协作文档；
- GitHub Issue/PR 模板使用 AlphaForge 名称；
- 文档从 `.gitignore` 中显式放行；
- 密钥与运行产物上传前检查清单。

验收：

- 所有文档内部链接存在；
- README 命令与真实文件/端口一致；
- 不包含真实 `.env` 值或本地私有报告；
- `git check-ignore` 证明 `docs/alphaforge/**` 可追踪，而 `agent/.env` 和运行产物继续忽略。

## P1：前端收敛为一个产品路径

目标：用户只需理解“问题 → 计划 → 确认 → 运行 → 报告”。

重点：

- `/` 作为唯一研究入口；
- 显式计划确认，不再创建后自动确认；
- 统一 V3 客户端、状态和错误合同；
- 修复 `/api/veriquant` 开发代理；
- 运行页可见选中研究组、预算、阶段、失败代码、取消和恢复；
- 正式报告使用 GFM 渲染并 answer-first；
- 所有指标展示权威标签：官方、辅助、无证据；
- 修正过时 FactorDAG/研究 Python 文案；
- 旧 Campaign 页面只做兼容重定向或开发者入口。

验收详见 [前端产品需求](FRONTEND_PRODUCT_REQUIREMENTS.md)。

## P2：报告质量与研究闭环

目标：报告不只说明“跑了什么”，还明确回答“发现是否可靠、缺什么、下一步怎么证伪”。

每份报告必须包含：

- 一句话结论与研究处置；
- Evidence 等级和合法结果类；
- 测试范围、数据范围、样本和代理变量；
- 假设、方法和变体；
- 支持证据与反对证据；
- 成本、稳定性、增量性或模式对应诊断；
- 明确限制；
- 问题特定的下一实验；
- 可展开的复现链接，不在首页堆哈希。

验收：任意公开数字都能追到 Evidence/辅助收据；没有数字时给非空诊断，不生成空成功报告。

## P3：六组真实工作能力

目标：每组不仅“有角色”，还具备 native data + native method + fail-closed 的代表能力。

每组至少三个任务：

1. 本组原生数据与原生方法；
2. 稳健性或专用输出合同；
3. 数据/安全缺口并失败关闭。

重点补强：

- 预期与事件：冻结公告/预测与 event/publication/availability 时钟；
- 另类数据：历史文档语料、实体映射和时点合格窗口；
- 宏观状态：真正按可知时间划分状态，不使用横截面常数替代；
- 组合增量：已登记因子/组合的可见证据、残差化和增量评价；
- 市场结构：成本、冲击、容量和成交约束；
- 基本面：财报可得时点、修订和行业/规模控制。

## P4：从辅助线索到官方可见 Evidence

目标：让标准表进入独立评价，而不是只做一致性检查。

优先顺序：

1. `RegressionTable` 官方重算与诊断；
2. `RegimeComparisonTable`；
3. `EventTable`；
4. `DiagnosticTable`；
5. `DatasetAssessmentTable`；
6. ScoreTable 的成本、增量与 Promotion 前置门禁。

每个评价器必须覆盖正向、负向、空表、样本不足、NaN、零方差、共线、事件时点缺失和 PIT 无效。

## P5：研究质量而非只看显著性

目标：把最新回归线索变为可以严格否定或保留的 Alpha 候选。

对当前示例问题的下一轮：

- 定义每日评分和 rebalance 规则；
- 做 walk-forward 样本外评价；
- 报告 RankIC、ICIR、分位数组合收益和稳定性；
- 计算换手、价差、冲击和容量；
- 直接计算与 50 日动量的相关和残差增量；
- 用可知 Shibor 划分高低状态；
- 扩大历史时间和股票池；
- 经过独立 Evidence 后再讨论 Promotion。

## P6：运行与部署收敛

目标：状态、服务和产物只有一个可信来源。

- 修复根 `state.json` 与新 Harness 收据漂移；
- 提供 AlphaForge-only Docker 服务并测试回环映射；
- 统一 artifact root、manifest 和 API 投影；
- 加入租约、心跳、过期运行恢复、幂等和取消测试；
- LLM 不可用时，状态、Evidence、报告读取和停止能力仍可工作；
- 增加 Docker smoke、前端 E2E 和报告截图回归。

## 暂不进入路线图

以下工作在研究产品、Evidence、前端和部署收敛前不应优先：

- 真实自动下单；
- 新 Broker 接口；
- 无预算的 mutation/crossover 扩张；
- 让模型读取 sealed 反馈进行下一轮搜索；
- 再建一套 Campaign/Workbench/报告运行时；
- 为了“通过”而给具体问题写硬编码分支。
