# AlphaForge 产品理念

## 一句话定义

AlphaForge（千因研究院）是一套面向量化研究的多专业智能体 Research OS：它把自然语言研究问题转化为可审计、可恢复、可复现的研究 Campaign，并将“自由探索”与“金融事实权限”分开。

## 我们为什么做它

传统量化研究平台擅长固定公式、固定数据和固定回测，但面对开放问题时，研究者仍需手工拆解问题、找数据、写实验、处理失败、组织证据和写报告。通用 Agent 擅长开放探索，却容易把模型判断、临时代码和一次性回测误当成可信结论。

AlphaForge 试图把两者组合：

- 让 Agent 做它擅长的事：理解问题、提出假设、选择研究路径、调查数据、设计实验、审查与修订、解释结果；
- 让确定性系统做它必须做的事：数据冻结、时点语义、代码审查、隔离执行、标准输出、统计评价、Evidence、晋级、风险和审计；
- 让用户看见真实进展与限制，而不是只得到一个看似确定的聊天答案。

## 目标用户

### 研究负责人

希望用一句自然语言问题启动一轮结构化研究，并得到包含结论、证据等级、限制和下一实验的正式报告。

### 量化研究员

希望并行探索基本面、事件、市场结构、另类数据、宏观状态和组合增量方向，并保留每次实验与失败的机器收据。

### 产品和风控负责人

希望明确知道哪些结果是 Agent 草案、哪些是辅助研究、哪些是官方 Evidence，以及系统有没有越过权限边界。

### AI 编程代理与外部协作者

希望从文档中快速理解真实入口、合同、状态、测试和非目标，不需要靠猜测重建系统。

## 核心产品原则

### 1. 先回答问题，再展示系统

报告和结果页必须先给一句话结论、处置建议和证据等级。哈希、内部阶段和技术细节放在可展开的证据详情中。

### 2. 研究自由，权限机械化

Agent 可以自由规划和修订研究，但不能凭提示词获得官方指标、晋级、风险、订单或账本权限。权限由代码、白名单、隔离和独立服务执行。

### 3. 每一种诚实结果都算产品结果

一次合法研究可以结束为：

- `EVALUATED_RESEARCH_RESULT`：完成确定性评价；
- `NEGATIVE_RESEARCH_RESULT`：完成评价但不支持假设；
- `PARTIAL_RESEARCH_RESULT`：有可用工作，但某些正式门禁不可用；
- `DATA_OR_CAPABILITY_GAP_REPORT`：缺少数据、时间语义、工具、权限或评价器；
- `SYSTEM_FAILED`：只有基础设施真的失败时才使用。

“始终给结果”不等于“始终给正向 Alpha”。

### 4. 不把测试数量当研究质量

包级测试通过证明合同和不变量没有明显回归，不证明任意问题都能得到好结果。产品验收必须包含代表问题、真实路径、六组研究、正负结果、报告、复放与安全门禁。

### 5. 只运行需要的研究组

多 Agent 的价值来自专业分工和独立上下文，不来自角色数量。问题路由可以选择一到六组；未选择的组不消耗模型调用和实验预算。

### 6. 报告中的每个数字都有来源

LLM 可以解释数字，但不能发明、修改或提升数字的权威等级。前端只能显示后端明确允许的公开字段。

### 7. 可以恢复，不重复烧预算

Campaign 必须有稳定身份、幂等键、检查点、事件和恢复游标。恢复应从首个未完成阶段继续，不重复已提交的模型调用或实验。

## 六个专业研究组

| 研究组 | 主要问题 | 典型数据/方法 |
| --- | --- | --- |
| 基本面 | 估值、盈利质量、资产负债和现金流是否解释未来收益 | 财务时点、截面回归、质量/价值因子 |
| 预期与事件 | 预期变化和事件冲击是否产生可测影响 | 公告、预测、事件窗、EventTable |
| 市场行为与交易可行性 | 量价、流动性、微观结构和成本是否支持可交易性 | OHLCV、换手、冲击、容量、Regime |
| 另类数据 | 新闻、研报、文本或外部资料是否提供增量信息 | 文档来源、实体映射、数据集评估 |
| 宏观状态 | 信号在利率、波动、流动性和经济状态中是否稳定 | 宏观时点、状态划分、RegimeComparison |
| 组合增量 | 新候选在控制已有因子后是否仍有增量 | 相关、残差化、增量回归、组合约束 |

## 研究深度与协作方式

研究深度控制预算和验收强度：

- 快速探索：小预算、快速确认数据与方向，不应暗示完成官方评价；
- 标准研究：多组协作、受控实验、报告和可见评价；
- 严格验证：更强的稳健性、复放、负向测试和独立门禁，仍不自动等于晋级。

协作方式控制人机交互：

- 引导式：计划、数据准备或重要缺口处请求用户确认；
- 标准式：计划确认后自动运行到合法终态；
- 批处理式：适合已冻结问题集和统一预算，不应用于绕过确认或权限。

## 明确非目标

AlphaForge 当前不是：

- 收益保证或自动赚钱系统；
- 允许模型直接写账户、订单或账本的交易 Agent；
- 用单个 RankIC、Sharpe 或 p 值自动晋级候选的工具；
- 把 Qlib long-only 回测称为完整组合、风险、执行和会计链的系统；
- 让所有 500 个问题都调用真实模型的暴力跑分工程；
- 用漂亮前端隐藏数据缺口、辅助证据或失败状态的展示层。

## 成功标准

产品成功不是“页面能打开”，而是用户提出一个代表性问题后：

1. 系统保留问题语义并生成可读计划；
2. 用户知道数据范围、预算、研究组和停止条件；
3. 选中的研究组能独立工作或给出明确缺口；
4. 代码和数据经过可验证的安全边界；
5. 输出进入正确标准合同和确定性评价器；
6. 报告先回答问题，再呈现支持、反对、限制和下一实验；
7. 同一冻结输入可复放得到一致身份；
8. UI 不混淆辅助研究、官方 Evidence 和晋级。
