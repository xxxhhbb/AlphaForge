# Distilled Correction Patterns

## Many green modules, no working product

Multiple product services, manifests, stores, runtimes, and artifact roots cause API, terminal, Workbench, and report drift. Freeze one call graph and canonical manifest. Mark alternatives compatibility-only or audit-only; do not add another runtime.

## Acceptance fixture presented as research

Keep deterministic fixtures outside the real product path. Real model, review, sandbox, output, Evidence, and report receipts must share one run identity.

## Hard gates prevent research

Move fixed native-field qualification gates to background audit. Let the agent inspect approved sources, request data, disclose a proxy, or return a precise gap report. Evaluate the resulting data and code mechanically.

## Data tools exist but Evidence cannot consume them

Connect tool response → raw freeze → provenance → semantic mapping → available-at policy → canonical dataset → evaluator. Discovery success is not official readiness.

## Keyword routing changes the experiment

Compile a typed task plan separating goal, subject, method, required data, specialist roles, output contract, and report contract. Validate it before execution.

## Non-score outputs remain auxiliary

Add deterministic evaluators for Regression, Regime, Event, Diagnostic, and Dataset Assessment outputs. Promotion eligibility stays separate.

## Schema brittleness produces zero candidates

Derive schemas from typed contracts, safely normalize only representation differences, isolate invalid candidates, return redacted errors, and allow budgeted revision. Never invent official values.

## Report is an artifact dump

Lead with verdict, evidence level, tested variants, support/opposition, limits, and next experiment. Put hashes after the explanation and bind every number to Evidence.

## “Always return a result” becomes fake success

Guarantee a legitimate result class, not a positive Alpha. Negative, partial, and precise data-gap reports are valid outcomes; infrastructure failures are not.

## UI hides synchronous blocking

Use a durable manifest, leases, checkpoints, idempotency keys, atomic events, and polling. UI is a projection, not a second state machine.

## Unwrapped Vibe reuse breaks trust

Reuse Vibe runtime and tools through capability wrappers. Freeze and classify outputs before evaluation; never give the LLM official authority.

## Running all catalog questions before fixing blockers wastes effort

Statically validate the full catalog, then run a balanced real suite across goals, data families, specialists, outputs, outcome classes, and security boundaries.
